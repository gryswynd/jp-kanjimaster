# Android build — setup, manual edits, and beta distribution

The `android/` directory is **gitignored** (same convention as `ios/`) and is
generated by `npx cap add android`. Everything below documents (a) the machine
tooling, (b) the **manual edits inside `android/`** that a fresh
`cap add android` will NOT recreate, and (c) the build + beta-distribution flow.
If `android/` is ever lost, re-run `npx cap add android` and replay section (b).

---

## (a) Machine tooling (installed 2026-06-12 via Homebrew)

- **JDK 21**: `brew install openjdk@21` →
  `JAVA_HOME=/usr/local/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home`
- **Android SDK** (command-line tools): `brew install android-commandlinetools` →
  SDK root `/usr/local/share/android-commandlinetools`
  - Packages: `sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"`
    (licenses accepted via `yes | sdkmanager --licenses`)
- **Android Studio**: `brew install --cask android-studio` — optional for
  builds (Gradle + the SDK above are enough) but handy for logcat, device
  manager, and the emulator. Point it at the existing SDK root on first launch.
- Gradle finds the SDK via `android/local.properties`
  (`sdk.dir=/usr/local/share/android-commandlinetools`) — no shell env needed.
  Optional `~/.zshrc` additions for convenience (`adb` etc. on PATH):

  ```sh
  export JAVA_HOME="/usr/local/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home"
  export ANDROID_HOME="/usr/local/share/android-commandlinetools"
  export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"
  ```

## (b) Manual edits inside android/ (replay after a fresh `cap add android`)

1. **`android/local.properties`** (gitignored by the android template anyway):
   `sdk.dir=/usr/local/share/android-commandlinetools`

2. **`android/app/src/main/AndroidManifest.xml`** — mirrors iOS `Info.plist`:
   - Inside `<activity>` (MainActivity), after the LAUNCHER intent-filter —
     `kanjimaster://` deep links (mirrors `CFBundleURLSchemes`):
     ```xml
     <intent-filter>
         <action android:name="android.intent.action.VIEW" />
         <category android:name="android.intent.category.DEFAULT" />
         <category android:name="android.intent.category.BROWSABLE" />
         <data android:scheme="kanjimaster" />
     </intent-filter>
     ```
   - At manifest top level — visibility of the companion game app (mirrors
     `LSApplicationQueriesSchemes`):
     ```xml
     <queries>
         <intent>
             <action android:name="android.intent.action.VIEW" />
             <data android:scheme="rikizoadventure" />
         </intent>
     </queries>
     ```
   - Permissions (next to INTERNET) — AudioDojo records via `getUserMedia`
     (mirrors `NSMicrophoneUsageDescription`):
     ```xml
     <uses-permission android:name="android.permission.RECORD_AUDIO" />
     <uses-permission android:name="android.permission.MODIFY_AUDIO_SETTINGS" />
     ```
   - Notification/vibrate permissions are merged in automatically by the
     `@capacitor/local-notifications` and `@capacitor/haptics` plugin manifests
     — do NOT add them by hand.

3. **`android/app/build.gradle`** — two edits:
   - `versionName "0.1.0"` (keep aligned with `appVersion` in `index.html`;
     bump `versionCode` per release build).
   - A `signingConfigs.release` block reading the four `RIKIZO_UPLOAD_*`
     properties from `~/.gradle/gradle.properties`, applied to the `release`
     buildType when present (see "Release signing" below for the exact shape).

4. **Icons & splash** — regenerate, don't hand-edit `res/mipmap-*`:
   ```sh
   npx capacitor-assets generate --android --assetPath resources
   ```
   Sources live in `resources/` (committed): `icon-only.png`,
   `icon-foreground.png`, `icon-background.png`, `splash.png`, `splash-dark.png`
   — all derived from the iOS app icon (vermilion 力 on `#F2ECDE` washi).

5. **説明 mode selection-menu suppression** — three files (full source in the repo
   working tree at these paths; iOS counterpart in `docs/ios-native.md`):
   - `android/app/src/main/java/com/rikizo/app/MainActivity.java` — owns the
     `public static volatile boolean suppressSelectionMenu` flag and a `RkSelection`
     JS bridge (`@JavascriptInterface setSuppressed(boolean)`) the web layer calls
     from `app/shared/select-explain.js` on 説明 mode enter/exit.
   - `android/app/src/main/java/com/rikizo/app/RkCapacitorWebView.java` — a
     `CapacitorWebView` subclass that overrides `startActionMode(...)` and wraps the
     selection `ActionMode.Callback`/`Callback2`, clearing the menu in
     `onPrepareActionMode` so the **async** text-classifier repopulation can't bring
     the floating toolbar back. Keeps the selection alive (empty toolbar = invisible).
     A plain `onActionModeStarted` + `menu.clear()` is NOT enough on modern Android —
     that was the first attempt and the toolbar still flashed back.
   - `android/app/src/main/res/layout/capacitor_bridge_layout_main.xml` — overrides
     Capacitor's layout (app res beats library res) to inflate `RkCapacitorWebView`
     instead of the stock `CapacitorWebView`. Same `@id/webview`.

## (c) Build, install, distribute

```sh
# Full sanctioned build (runs ALL content gates: stories/audio/fonts/…)
npm run sync:android

# Debug APK
cd android && ./gradlew assembleDebug
# → android/app/build/outputs/apk/debug/app-debug.apk

# Install on a phone over USB (enable Developer options + USB debugging first)
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Reminder: `sync:android` runs `build:www`, so the usual content rules apply —
if you edited Japanese content you must `npm run gen:audio` (needs
`GOOGLE_TTS_API_KEY` + ffmpeg) and `npm run vendor:fonts` first, or the
validate-audio / validate-fonts gates fail the build.

### Release signing (beta)

The upload keystore lives OUTSIDE the repo at `~/keystores/rikizo-upload.jks`.
Credentials go in `~/.gradle/gradle.properties` (machine-global, never
committed):

```properties
RIKIZO_UPLOAD_STORE_FILE=/Users/joel/keystores/rikizo-upload.jks
RIKIZO_UPLOAD_KEY_ALIAS=rikizo-upload
RIKIZO_UPLOAD_STORE_PASSWORD=…
RIKIZO_UPLOAD_KEY_PASSWORD=…
```

`android/app/build.gradle` has a `release` signingConfig reading those four
properties (falls back to unsigned if absent). Build with
`cd android && ./gradlew assembleRelease`.

### Firebase App Distribution

- Firebase project: `project-9c65f87c-e8c8-409b-843` (see `.firebaserc`).
- One-time: register an Android app with package `com.rikizo.app` in the
  Firebase console (or `npx firebase-tools apps:create android`), note the
  App ID (`1:…:android:…`), and create a `beta` tester group under
  App Distribution.
- Distribute a build:
  ```sh
  npm run dist:android   # assembleRelease + upload to the beta group
  ```
  (Requires `npx firebase-tools login` once, and the `FIREBASE_ANDROID_APP_ID`
  value inside the npm script to be set to the real App ID.)

## Platform notes

- **Hardware back button**: handled in `index.html` `_nativeBoot()` —
  dismisses `.jp-return-overlay` popups → returns Home (`renderMenu()`) →
  minimizes the app. Without that listener Capacitor would exit the app on
  every back press.
- **Safe areas**: the CSS uses `max(Npx, env(safe-area-inset-*))` everywhere,
  so collapsed insets on Android degrade to the fixed padding. Capacitor 8
  targets SDK 36 (edge-to-edge); check status/nav-bar overlap on device.
- **Server**: the tutor backend accepts Android clients as-is while
  `ATTEST_BYPASS` is on. When iOS App Attest verification lands, Android needs
  the Play Integrity equivalent (`server/lib/attest.js`).
- **Google Play is NOT set up** — bundled content (~346 MB) exceeds Play's
  200 MB base-AAB limit; shipping to Play later requires Play Asset Delivery.
